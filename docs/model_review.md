# 对“梳理飞机调姿因果图”讨论的核对

这份说明核对用户分享的同名 ChatGPT 讨论，作为建模决策记录；引用讨论中的方案不等于采用其全部结论。

## 保留的结论

1. 全流程在同一个世界坐标系内记录，R、t 仍可表示部件实际运动；无需把每一步说成坐标系转换。
2. 生成动作须由执行前可用的定位坐标、设计目标和控制规则决定。用操作前后数据拟合实际运动适合重建，但不能反过来当作生成该结果的原因。
3. 三维完整刚体配准需要足够的非退化几何约束；本模型每段使用三个不共线点。
4. 对合后锁紧的部件，共享后续刚体运动。这里前对合只动 A，后对合只动 C，最后动整机。

## 需要修正的结论

“加入部件状态 Z，就能扩大溯源范围”需要区分两种 Z：

- 真实物理状态 G 是各点真实位置的共同原因。某个点的测量值改变，不会自动改变真实 G。
- 估计状态 Z_hat = g(Y_1,...,Y_n) 是坐标计算的结果。仅当控制器实际使用它时，才有 Z_hat → H → 后续真实坐标。

若 H=f(Z_hat)、Z_hat=g(Y)，则 H=f(g(Y))。将计算拆成两个节点能解释机制，但没有创造新的物理作用。现代码对前后对合已经先估计部件姿态再算 H；图为了简洁将姿态估计折叠在动作节点内部。

“非定位点 A4 局部异常 → 真实部件状态 → 接口点”不是自动成立的。若 A4 只是局部偏差或测量噪声，既不参与定位，又没有力学耦合模型，它不会凭借共享刚体标签影响其他点。若要增加这条边，应给出夹持/载荷/形变传播机制，或者明确 A4 参与实际姿态估计和控制。

前对合只移动 A 时，H_front 不能直接作用于同一步 B2；影响 B2 需要后续整机动作等实际途径。当前固定图按这一规则生成。

“测量误差不进入后续状态”应表述为不直接复制进物理状态。反馈模型中测量误差可以改变控制动作，进而改变后续真实位置。本代码区分了这两种途径。

因此，项目采用已明确的“定位观测 → 估计姿态/计算动作 → 执行运动 → 下一阶段坐标”，不以增加抽象状态节点或全连接边来弥补缺少的物理机制。
